# 沉浸模式可扩展交互框架设计

## 目标

为沉浸模式增加可扩展的近距离交互能力。首个交互对象仅为房门：玩家靠近并大致看向门时显示提示，按 `F` 在开门和关门之间切换，门扇以具有加速、减速和惯性的动画绕铰链运动。

## 范围

- 建立可注册多个交互目标的通用交互系统。
- 首期只注册当前场景中的房门。
- 交互只在沉浸模式完成自动进门、进入自由活动阶段后启用。
- 保留现有自动进门动画、移动、跳跃、碰撞、通行和其他物理逻辑，不以门的交互状态修改任何物理判定。
- 不为平面、布局或自由漫游模式启用该交互。

## 交互判定

每个交互目标提供稳定 ID、世界坐标、最大距离、最低视线点积、提示文案、触发方法和逐帧更新方法。交互系统每帧更新目标，并从满足条件的目标中选择得分最高者作为当前焦点。

门的最大交互距离为约 2.5 米。视线判定使用较宽松的圆锥，只要求门位于玩家视野中心附近，不要求射线精确命中门网格。距离和视线方向共同参与候选评分，为以后同时存在多个交互对象预留确定的选择规则。

## 输入与提示

- 有焦点目标时，在画面下部中央显示紧凑提示：`F 开门` 或 `F 关门`。
- 没有目标、离开范围、视线转开、退出沉浸模式或仍处于自动进门阶段时隐藏提示。
- `F` 只响应非重复的 `keydown`，长按不会连续切换。
- 门动画进行中再次按 `F` 时切换目标状态，并从当前角度平滑反向。

## 门动画

门交互对象维护当前开合进度、目标进度和角速度。逐帧使用阻尼弹簧更新进度，使门扇自然起步、减速并带有轻微惯性；最终稳定在现有关闭角 `0` 或房间配置决定的现有开启角。

交互动画只写入现有 `doorPivot.rotation.y`。现有碰撞体、门洞、玩家位置约束和沉浸模式进入过程不做调整。

## 代码边界

- `src/three/interaction.ts`：交互目标协议、注册表、宽松视线选择及触发逻辑。
- `src/three/doorInteraction.ts`：把现有门枢轴适配成通用交互目标，并维护门动画状态。
- `src/components/hud/InteractionPrompt.tsx`：只负责渲染当前交互提示。
- `src/components/RoomScene.tsx`：注册房门、把相机姿态交给交互系统、处理 `F` 键并向 HUD 发布焦点文案。

通用交互层不依赖 React 状态；HUD 状态只在提示内容实际变化时更新，避免逐帧触发 React 渲染。

## 异常与生命周期

- 找不到 `doorPivot` 时跳过注册，不显示提示且不影响场景。
- 房间结构重建时清理旧目标并为新的门对象重新注册，避免保存已销毁的 Three.js 对象引用。
- 组件卸载时清空目标和提示。

## 验证

- 单元测试覆盖距离限制、宽松视线锥、多个候选目标选择和 `F` 触发当前焦点。
- 单元测试覆盖门开关、动画收敛以及动画中途反向。
- 完整测试与生产构建必须通过。
- 按用户要求，不由 Codex 执行页面验收；实际交互手感由用户测试。

## 非目标

- 不增加灯、抽屉或家具交互。
- 不增加声音、准星、门把手动画或物理门碰撞。
- 不修改现有操作键位以外的行为。
